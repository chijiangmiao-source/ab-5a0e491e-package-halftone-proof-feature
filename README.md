# 专色稿蛇行抖动 · 逐像素复核工作台

包装印刷稿压缩到 2~8 个专色时，普通浏览器滤镜会因浮点舍入和扫描方向差异产生**无法复核**的网点。
本工具是一个**纯前端、离线**的 React + TypeScript + Canvas 应用：PNG 自行解码、误差以整数 1/16 记账，
制版员点击结果中的**任意像素**，都能看到它为何落入某一专色，并由独立的复算器即时核验。

不调用任何在线服务；无第三方 PNG/图像处理依赖（解压缩使用平台内置 `DecompressionStream`）。

## 快速开始

```bash
npm ci
npm run dev        # 本地开发 http://localhost:5173
```

其他脚本：

| 命令 | 作用 |
| --- | --- |
| `npm run test` | Vitest 单元测试（参数校验 / PNG 解码 / 抖动引擎，44 例） |
| `npm run build` | TypeScript 严格类型检查 + 生产构建到 `dist/` |

| `npm run serve` | 零依赖 Node 静态服务器（容器运行镜像使用，`PORT` 可覆盖） |

## Docker / Compose 验收

`compose.yaml` 提供两个服务：

- **`verify`（一次性验收）**：构建 Playwright 官方镜像，容器内依次执行 Vitest、类型检查/构建、
  Chromium 端到端测试；退出码即验收结论，不发布端口。

  ```bash
  docker compose build verify
  docker compose run --rm verify
  ```

- **`web`（长期运行的静态服务）**：多阶段构建出精简镜像（仅 `dist/` + Node 内置 http 静态服务器）。
  宿主端口由 `WEB_PORT` 覆盖，默认 8080：

  ```bash
  WEB_PORT=9090 docker compose up web
  # 浏览器打开 http://localhost:9090
  ```

## 使用流程

1. 上传 PNG（点击或拖拽）。非 PNG、签名错误、CRC 损坏、截断、zlib 失败等都会**就地报错**，
   不产生任何输出。
2. 输入 **2~8 个不重复的六位 RGB 专色**（如 `E30613`）。色板顺序即等距裁决优先级。
3. 设置 **0~255 透明阈值**：源像素 alpha **严格小于**阈值即输出透明。
4. 界面并排显示：
   - 原图（PNG 解码后 RGBA，棋盘格表示透明）；
   - 量化结果（仅专色 + 透明）；
   - 当前像素的**调整值 / 平方距离表 / 选色 / 四个传播去向**。
5. 在结果上移动（悬停）或点击（钉选）任意像素，右侧证据联动；传播目标与四角按钮可跳转。
   参数非法时结果区立即清空，修正后自动恢复——**绝不存在占位结果或固定输出**。

## 算法（可逐像素复核的精确定义）

按行蛇形（boustrophedon）扫描：偶数行 `y = 0,2,…` 左→右，奇数行 `y = 1,3,…` 右→左。

1. **透明判定**：`alpha < 阈值` 的像素输出 `(0,0,0,0)`，**不接收、不传播**误差；
   任何投向透明像素（或越界）的误差份额在传播端**直接丢弃**。
2. **累计误差加入**：对不透明像素，每通道计算
   `调整值 = clamp(源值 + 累计误差/16, 0, 255)`。
   全部以 1/16 为单位的 `Int32` 整数记账，不存在浮点。
3. **四舍五入**：调整值半数**向上**取整（`floor((n16 + 8) / 16)`），得到整数 RGB。
4. **平方距离选色**：对色板逐项求
   `ΔR² + ΔG² + ΔB²`，取最小值；**只有严格更小才替换**，因此等距时色板中**靠前者**胜出。
5. **量化误差**：`e = 四舍五入后的整数调整值 − 选中专色`（整数，可正可负）。
6. **Floyd–Steinberg 传播**：
   - 偶数行：右 7/16、左下 3/16、正下 5/16、右下 1/16；
   - 奇数行水平镜像：左 7/16、右下 3/16、正下 5/16、左下 1/16（UI 按屏幕几何方位标注）；
   - **单份贡献** `e × 权重 / 16`（记账单位 1/16）遇半数**向远离零方向取整**
     （`sign · floor((|e·w| + 8) / 16)`）；越界或透明目标丢弃。

> 半数规则并非空转：量化误差恰为 **8** 时，四份贡献分别是 3.5、1.5、2.5、0.5，
> 全部落半数，按远离零记为 4、2、3、1（单测对这一手算布局逐份断言）；
> 另有在 24×17 随机图上统计大量 `|e·w| ≡ 8 (mod 16)` 份额的守卫测试。
> 误差必须取自**取整后**整数（流程规定：先取整、再选色、再算误差）——
> 若误用取整前小数误差，逐份记账会偏离规定值（例如灰 100 列的第二行会因此错误翻白，
> 该反例已作为回归测试固定）。累计误差账全程为纯 `Int32`，无浮点。

证据面板为每个像素展示：源 RGBA、入向累计误差账（1/16）、夹取标记、调整值、取整值、
各色平方距离、等距标记、量化误差、四向权重/目标/记账值/丢弃原因、扫描序号与行方向。

### 独立复算

`src/lib/dither.ts` 的 `recomputeFromEvidence` **不读取引擎输出**，仅凭证据中记录的
「源像素 + 累计误差账」独立重走 夹取 → 四舍五入 → 距离比较 → 等距裁决 → 四向去向，
与证据逐项比对；任何不一致都会在面板 ⑤ 中逐条列出。单测还包含一个不共享代码路径的
参照实现，对多组随机图全量交叉验证输出像素与每格误差账。

## 支持的 PNG

8/16 位 RGB / RGBA / 灰度 / 灰度+Alpha，1/2/4/8 位索引色（PLTE、tRNS）与子字节灰度，
Adam7 交错；五种行过滤器全部实现；IHDR/PLTE/IDAT/IEND 与常见辅助块、CRC32 校验。
**缺少 IEND 结束块（在尾部截断）同样判为解码失败并就地报错、清空输出。**
不支持的关键块或位深组合明确报错。

```
  main.tsx, styles.css
tests/
  fixtures/png.ts     零依赖确定性 PNG 夹具生成器
  e2e/app.spec.ts     Playwright 验收（12 个场景，含灰度逐份取整回归、缺 IEND 截断、外部请求禁令）

```
